\## 1. 작업 목표



기획서 9.10.4 중복 마물 변환 규칙을 기준으로 마물 카드 보유 구조를 구현한다. CardData는 카드의 고정 정보만 관리하고 보유 수량은 PlayerProgressManager에서 관리한다. 희귀도별 보유 한도와 초과분 정수 변환, 덱 편성 시 보유 검증을 함께 구현한다.

\## 3. 희귀도 규칙



기획서 7.5와 9.10.4를 기준으로 희귀도별 수치를 정의했다.



| 희귀도 | 보유 및 편성 한도 | 초과 변환량 |

| --- | --- | --- |

| 일반 | 3장 | 정수 2개 |

| 희귀 | 2장 | 정수 4개 |

| 특수 | 1장 | 정수 8개 |

| 전설 | 1장 | 정수 16개 |



희귀도는 마물 데이터에 저장하고 카드 데이터는 소환 마물의 희귀도를 참조한다. 같은 마물의 희귀도가 카드와 마물에서 다르게 설정되는 문제를 막기 위해 저장 위치를 하나로 유지했다.



\---



\## 4. 보유 규칙



\- 처음 획득한 카드는 보유 목록에 1장으로 등록

\- 이미 보유한 카드는 희귀도 한도까지 수량 증가

\- 한도를 초과한 카드는 마물의 정수로 자동 변환

\- 변환 여부는 선택할 수 없음

\- 시작 보유 카드도 보유 수량에 포함

\- 카드 해체 기능은 제공하지 않음

\- 보유 마물 데이터는 강화 단계와 경험치만 관리



30일차의 중복 포획 강화 재료 5개 고정 지급은 희귀도별 정수 변환으로 교체했다.



\---



\## 5. 덱 검증 항목



기획서 6.13.2의 전투 시작 차단 항목을 기준으로 검증을 확장했다.



\- 덱 장수 불일치

\- 희귀도별 중복 제한 초과

\- 미보유 카드 포함

\- 보유 수량 초과 편성

\- 빈 카드 데이터

\- 빈 카드 ID

\- 마물 데이터가 없는 손상된 카드



동일 카드 제한 값을 직접 지정하던 방식은 제거하고 희귀도 규칙에서 자동으로 결정한다. PlayerProgressManager가 없는 씬에서는 보유 검증만 생략하고 나머지 검증은 그대로 수행한다.

\## 6. 데이터 정리



\- 촉수 카드와 촉수 마물의 ID를 C006, M006으로 변경

\- 마물 에셋 6종에 희귀도 설정

\- 마물 에셋 6종에 포획 보상 카드 연결

\- 누락된 성욕 피해 기본값 복구

\- 누락된 레벨 성장 수치 복구



기존 C003과 M003을 독슬라임과 촉수가 함께 사용하고 있었다. 보유 수량을 카드 ID로 관리하므로 두 카드가 같은 카드로 처리되는 문제가 발생해 ID를 분리했다.



28일차에 추가한 레벨 성장 수치가 마물 에셋에 저장되어 있지 않아 레벨이 올라도 능력치가 증가하지 않는 상태였다. 성장 수치와 성욕 피해를 에셋에 기록해 정상 동작하도록 복구했다.

\## 8. 작업 결과



마물 카드의 보유 수량을 진행 데이터에서 관리하도록 구조를 정리했다. 희귀도별 보유 한도를 초과한 카드는 마물의 정수로 자동 변환되며, 보유하지 않은 카드나 보유 수량을 초과한 덱은 전투를 시작할 수 없다.



기획서 6.7.3과 6.11의 중복 획득 선택 방식은 9.10.4의 자동 변환 규칙과 충돌하므로 9.10.4를 기준으로 구현했다. 기획서에서 선택 방식 설명을 정리할 필요가 있다.



기획서 6.8.2의 시작 덱 30장은 마물 11종이 필요하므로 현재 마물 6종으로는 구성할 수 없다. 시작 덱 데이터 제작은 마물 타입 데이터가 추가된 이후에 진행한다.
