\# Project V 44일차 개발일지



\---



\## 1. 작업 목표



43일차까지는 게임을 끄면 재화, 레벨, 강화한 마물, 그리모어 강화, 구매한 소모성 아이템이 모두 처음 상태로 돌아갔다. 기획서 15장의 저장 규칙을 구현해 진행 데이터를 파일에 남기고, 다시 켰을 때 이어서 진행하게 한다.



자동 저장 1칸과 수동 저장 3칸을 두고, 메인 메뉴에 이어하기, 새 게임, 불러오기를 넣는다.



\---



\## 2. 구현 내용



\- 저장 데이터 구조 추가

\- 저장 파일 쓰기, 읽기, 삭제 추가

\- 무결성 검사값과 백업 복구 추가

\- 진행 데이터를 저장 데이터로 옮기고 되돌리는 처리 추가

\- 자동 저장 시점 연결

\- 화면 오른쪽 위의 저장 표시 추가

\- 누적 플레이 시간 추가

\- 저장 화면 추가

\- 메인 메뉴에 이어하기, 새 게임, 불러오기 추가

\- 지역 선택에 저장 버튼 추가

\- 저장용 전체 카드 목록 연결 추가

\- 저장 화면용 이미지 요청문 작성과 아이콘 적용



\---



\## 3. 저장 칸과 저장 대상



기획서 15.2에 따라 저장 칸은 4개다.



| 칸 | 수 | 쓰는 방법 |

| --- | --- | --- |

| 자동 저장 | 1 | 정해진 시점에 게임이 저장 |

| 수동 저장 | 3 | 플레이어가 칸을 골라 저장 |



기획서 15.2의 진행 저장 항목 가운데 지금 있는 것을 모두 담았다.



| 분류 | 저장하는 값 |

| --- | --- |

| 재화 | 골드, 마물의 정수, 욕망의 파편 |

| 성장 | 누적 경험치 |

| 카드 | 보유 카드, 사본 번호, 사본별 강화 단계 |

| 덱 | 프리셋 5개의 이름과 편성, 사용 중인 프리셋 번호 |

| 소환사 | 장착한 액티브 스킬과 패시브, 패시브별 단계 |

| 그리모어 | 노드별 단계 |

| 소모성 아이템 | 종류별 수량, 장착한 아이템 |

| 기록 | 누적 플레이 시간, 저장 일시, 게임 버전, 저장 데이터 버전 |



플레이어 레벨은 저장하지 않고 누적 경험치에서 계산한다. 마물 도감 기록과 사용한 패시브 포인트도 저장하지 않고 불러올 때 보유 카드와 패시브 단계에서 다시 계산한다.



카드, 스킬, 패시브, 노드, 아이템은 ID 문자열로 적는다. 에셋의 위치나 이름이 바뀌어도 ID가 같으면 저장 데이터가 유지된다.

\## 4. 저장 파일



기획서 15.8에 따라 JSON으로 저장하고 간단한 가림과 무결성 검사값을 적용했다.



| 항목 | 내용 |

| --- | --- |

| 저장 위치 | 사용자 데이터 폴더의 Saves 폴더 |

| 파일 | auto.sav, manual1.sav, manual2.sav, manual3.sav |

| 백업 | 같은 이름의 .bak (직전의 정상 파일) |

| 겉 구조 | 파일 구분 문구, 저장 데이터 버전, 검사값, 진행 데이터 |

| 진행 데이터 | JSON을 열쇠 문자열과 XOR한 뒤 Base64로 적음 |

| 검사값 | 진행 데이터의 SHA-256 |



저장은 다음 순서로 한다.



| 순서 | 처리 |

| --- | --- |

| 1 | 임시 파일에 기록 |

| 2 | 임시 파일을 다시 읽어 형식, 검사값, 버전을 검사 |

| 3 | 기존 파일이 정상이면 백업으로 복사 |

| 4 | 임시 파일을 실제 파일로 교체 |



검사에 실패하면 임시 파일만 지우고 기존 파일은 그대로 둔다. 기존 파일이 이미 깨져 있으면 백업으로 복사하지 않아, 정상 백업이 깨진 파일로 덮이지 않는다.



읽을 때 본 파일의 형식이나 검사값이 맞지 않으면 백업을 읽는다. 백업으로 복구했을 때는 기획서 15.4의 안내 문구를 표시한다. 둘 다 읽을 수 없으면 그 칸은 불러올 수 없는 칸으로 표시한다.



저장 데이터 버전은 1이다. 기획서 15.9에 따라 지금 버전보다 높은 저장은 불러오지 않고, 낮은 저장은 읽을 때 지금 구조로 바꾼다. 아직 버전이 하나뿐이라 바꾸는 내용은 없다.

\## 5. 자동 저장 시점



기획서 9.17과 15.6의 시점 가운데 지금 있는 기능에 해당하는 것을 연결했다.



| 시점 | 처리 |

| --- | --- |

| 새 게임 시작 | 바로 저장 |

| 전투 시작 직전 | 바로 저장 |

| 전투 승리, 패배 결과 확정 | 바로 저장 |

| 상점 구매 | 바로 저장 |

| 마물 강화 | 바로 저장 |

| 그리모어 강화 | 바로 저장 |

| 패시브 해금과 강화 | 바로 저장 |

| 소모성 아이템 사용 | 바로 저장 |

| 화면 이동 | 마지막 저장 뒤에 바뀐 것이 있을 때만 저장 |

| 게임 종료 | 마지막 저장 뒤에 바뀐 것이 있을 때만 저장 |



덱 편성은 카드를 옮길 때마다 저장하지 않는다. 기획서에는 덱 저장을 선택한 시점에 저장한다고 되어 있는데 지금 덱 편성 화면에는 저장 버튼이 없어, 화면을 나갈 때 저장한다. 스킬과 패시브 장착, 소모성 아이템 장착도 같은 방식이다.



전투 중의 상태는 진행 데이터에 들어 있지 않다. 전투 도중에 저장되거나 게임이 꺼져도 전투 시작 전의 진행만 남는다. 소모성 아이템은 사용한 순간 저장하므로 전투를 그만둬도 돌아오지 않는다. (기획서 15.7)



저장하면 화면 오른쪽 위에 표시가 1.9초 동안 나타난다. 자동 저장, 저장 완료, 저장 실패의 세 가지다. 표시는 진행 데이터 관리자에 붙어 씬이 바뀌어도 유지된다.

\## 6. 게임 시작 흐름



저장이 생기면서 "지금 메모리에 있는 진행이 누구의 것인가"를 정해야 했다. 게임을 켠 직후의 진행 데이터는 처음 상태인데, 이 상태에서 상점 구매 같은 자동 저장 시점을 만나면 기존 자동 저장이 처음 상태로 덮인다.



이를 막기 위해 게임 시작 여부를 따로 둔다.



| 상황 | 처리 |

| --- | --- |

| 저장 파일이 없음 | 지금 상태를 새 게임으로 삼아 바로 시작하고 자동 저장 |

| 저장 파일이 있음 | 이어하기, 새 게임, 불러오기 가운데 하나를 고를 때까지 시작하지 않음 |

| 시작하기 전 | 자동 저장하지 않음, 메인 메뉴의 다른 메뉴가 눌리지 않음 |



| 버튼 | 동작 |

| --- | --- |

| 이어하기 | 불러올 수 있는 칸 가운데 저장 일시가 가장 최근인 칸을 불러옴 |

| 새 게임 | 진행 데이터를 처음 상태로 되돌리고 자동 저장 칸에 저장 |

| 불러오기 | 저장 화면으로 이동 |



새 게임은 진행 중이거나 저장 파일이 있으면 한 번 더 눌러야 시작한다. 새 게임이 바꾸는 칸은 자동 저장뿐이고 수동 저장 3칸은 남는다.



전투 씬만 따로 실행했을 때는 게임을 시작한 상태가 아니므로 저장 파일을 건드리지 않는다.

새 씬 09 SaveLoad를 추가했다.



| 영역 | 내용 |

| 오른쪽 상세 | 레벨과 경험치, 재화, 보유 카드 수, 사용 중인 덱, 그리모어 강화 단계 합, 소모성 아이템 수, 플레이 시간, 저장 일시, 게임 버전 |

| 버튼 | 저장, 불러오기, 삭제 |



| 들어온 곳 | 할 수 있는 것 |

| --- | --- |

| 메인 메뉴의 불러오기 | 불러오기, 삭제 |

| 지역 선택의 저장 버튼 | 저장, 불러오기, 삭제 |



| 동작 | 확인 |

| --- | --- |

| 빈 칸에 저장 | 바로 저장 |

| 데이터가 있는 칸에 저장 | 한 번 더 눌러 덮어쓰기 (기획서 15.5) |

| 게임 진행 중에 불러오기 | 한 번 더 눌러 불러오기 |

| 삭제 | 두 번 더 눌러 삭제, 백업도 함께 삭제 (기획서 15.28) |



자동 저장 칸에는 직접 저장할 수 없다. 비어 있는 칸과 불러올 수 없는 칸은 아이콘과 글자색으로 구분하고, 불러올 수 없는 칸에는 이유를 적는다.

\## 8. 불러올 때의 처리



저장 데이터의 값을 그대로 믿지 않고 지금 게임의 규칙에 맞춘다.



\- 지금 게임에 없는 ID는 건너뛰고 건너뛴 수를 기록으로 남긴다

\- 재화는 보유 한도 안으로, 경험치는 최대 누적 경험치 안으로 맞춘다

\- 강화 단계, 패시브 단계, 그리모어 단계, 아이템 수량은 각 규칙의 범위 안으로 맞춘다

\- 같은 카드나 같은 사본 번호가 두 번 적혀 있으면 하나만 받는다

\- 덱은 카드 ID와 사본 번호로 보유 사본을 다시 찾아 편성한다

\- 사용한 패시브 포인트는 패시브 단계에서 다시 계산한다

\- 마물 도감 기록은 보유 카드의 최고 강화 단계에서 다시 만든다

\- 저장 파일에 없는 항목은 빈 값으로 채운다



카드 ID를 카드로 되돌리려면 전체 카드 목록이 필요하다. 씬 구성 도구가 프로젝트의 모든 카드를 진행 데이터에 연결한다.

\## 10. 임시 처리와 미룬 항목



| 항목 | 지금 처리 | 정식 처리 시점 |

| --- | --- | --- |

| 수동 저장 위치 | 지역 선택 화면 | 월드맵 일차 |

| 이어하기, 새 게임, 불러오기 위치 | 메인 메뉴 | 타이틀 화면 일차 |

| 새 게임의 시작 재화 | 시험값 사용 항목을 따름 | 타이틀 화면 일차 |

| 지역, 스테이지, 히로인전, 포획 진행도 | 저장하지 않음 | 각 기능을 만드는 일차 |

| 설정, 도감, 갤러리의 공통 프로필 | 만들지 않음 | 각 기능을 만드는 일차 |

| 저장 칸의 현재 지역, 진행도, 대표 이미지 | 표시하지 않음 | 월드맵과 스테이지 일차 |

| 전투 중 종료 안내 | 없음 | 전투 준비와 편의 기능 일차 |

| Steam Cloud | 없음 | 출시 준비 |



43일차 일지에는 새 게임 흐름에서 시작 재화를 기획서 값으로 바꾼다고 적었다. 이번에는 바꾸지 않고 시험값 사용 항목을 따르게 했다. 남은 일차에서 강화, 그리모어, 상점을 바로 확인하려면 시험값이 필요하기 때문이다. 항목을 끄면 새 게임이 기획서 값(골드 500, 정수 5, 파편 3, 경험치 0)으로 시작한다.



저장 항목은 앞으로 늘어난다. 저장 데이터 버전을 파일에 적어 두었고, 파일에 없는 항목은 빈 값으로 읽히게 했으므로 항목을 추가해도 이번에 만든 저장을 읽을 수 있다.

\- 전체 스크립트 컴파일 오류 없음

\- Unity 컴파일 통과와 씬 UI 다시 구성으로 씬 11개 구성

\- 씬 11개와 프리팹의 스크립트 참조에 빈 칸 없음 (메인 메뉴 13개, 지역 선택 11개, 저장 화면 10개)

\- 진입 씬의 진행 데이터에 저장용 카드 17종 연결

\- 테마에 저장 아이콘 9종 연결

\- 저장 파일 처리 시험 27개 통과



저장 파일 처리 시험은 Unity 밖에서 실행했다. Unity의 JSON 변환 기능은 Unity 밖에서 동작하지 않아 같은 역할을 하는 다른 변환기로 바꿔 끼웠다. 확인한 것은 다음과 같다.



\- 쓰기와 읽기에서 수치와 한글이 보존됨

\- 파일 본문에 진행 값이 그대로 보이지 않음

\- 두 번째 저장부터 백업이 생기고 임시 파일이 남지 않음

\- 본 파일을 한 글자 바꾸면 백업으로 복구됨

\- 본 파일과 백업이 모두 깨지면 불러올 수 없는 칸으로 읽힘

\- 깨진 본 파일은 백업으로 복사되지 않음

\- 더 높은 버전의 저장은 쓰기 검사에서 거부되고 파일이 남지 않음

\- 가장 최근 칸 찾기, 삭제 시 백업 함께 삭제

\## 14. 다음 실행에서 확인할 내용



이번 일차에는 씬 구성까지만 실행했고 게임을 실행한 기록이 없다. 저장과 불러오기는 Unity 안에서 한 번도 동작시켜 보지 못했다. 다음 실행에서 가장 먼저 확인한다.

\- 저장 폴더에 auto.sav가 생기는지

\- 상점 구매, 강화, 전투 결과에서 자동 저장되는지

\- 다시 실행했을 때 메인 메뉴의 다른 메뉴가 잠기고 이어하기로 재화, 카드 강화, 덱, 그리모어, 소모성 아이템이 돌아오는지

\- 새 게임이 처음 상태로 되돌리는지

\- 저장 덮어쓰기, 불러오기, 삭제의 확인 단계

\- 43일차에서 넘어온 항목: 상점 구매 결과, 전투에서의 소모성 아이템 사용

\## 15. 작업 결과



진행 데이터가 파일에 남게 되어 성장과 경제가 실행을 넘어 이어진다. 42일차와 43일차 일지에서 저장 대상으로 적어 둔 값이 모두 저장 항목에 들어갔다.



저장 항목은 진행 데이터를 옮기는 곳과 되돌리는 곳 두 군데에만 있다. 지역과 스테이지 진행도를 만들 때 이 두 곳에 항목을 더하면 된다.



게임 시작 여부를 따로 두어, 이어하기를 고르기 전에 한 조작이 기존 저장을 덮어쓰는 일이 없다.
